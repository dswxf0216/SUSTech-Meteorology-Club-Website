# 腾讯云香港服务器迁移准备

此配置是迁移准备文件，不代表已经部署。不要直接在空库启动 web：
Payload 的空库初始化流程可能允许创建首个管理员。先恢复并验证现有用户。

## 已采用的限制

- 复用根目录 Dockerfile，在 Linux x86_64 构建机上构建，不在 2GB 服务器构建。
- PostgreSQL 不映射宿主机端口；网站仅绑定 127.0.0.1:3000，尚未公开。
- 数据库和 media 使用独立命名卷；禁止执行 `docker compose down -v`。
- 网站内存上限 1GB、数据库 384MB，日志轮转；上线后根据监测调整。
- 此文件不包含 HTTPS 代理、自动备份或 SMTP 配置；这些仍须在正式切换前完成。

## 迁移顺序

1. 确认 Railway PostgreSQL 的主版本、数据库大小、迁移记录和媒体存储位置。
2. 在 GitHub Actions 或其他 Linux 构建机生成镜像。保持镜像私有；不要将
   `.env`、数据库备份或媒体打包进镜像。记录镜像摘要/提交号以便回退。
3. 审查 `NEXT_PUBLIC_*` 的构建期替换，确保最终域名和服务器端同源校验一致。
4. 将本目录配置传到服务器的专用部署目录。服务器本地填写 `.env`，权限 600。
   POSTGRES_PASSWORD 使用随机十六进制；PAYLOAD_SECRET 保留旧生产值。
   POSTGRES_IMAGE 必须核对源库兼容性；18及以上镜像数据目录需另行适配。
5. 执行 `sudo docker compose config --quiet`，不要输出含密钥的完整配置。
6. 仅启动 postgres，制作源数据库完整备份并恢复到新库；先演练恢复。
   迁移涉及账号邮箱、密码哈希、内容等非公开数据，操作前取得用户确认。
7. 复制源媒体到新 media 卷，保留旧副本；确保应用 UID/GID 1001 可读写。
   如果 Railway 未持久保存文件，先确认哪些文件仍可恢复，不能以数据库代替媒体备份。
8. 核对用户角色、审批状态、内容和迁移记录，再启动 web；数据库 schema push
   始终关闭。启动可能执行项目已登记的生产迁移，必须先在恢复副本验证。
9. 通过服务器本机健康检查测试。随后配置域名、HTTPS 代理和最小防火墙规则，
   验证管理员登录、编辑申请审批、发布内容、图片上传和天气实况/历史图。
10. 设置数据库及媒体自动备份，并把加密副本存到服务器之外，演练恢复。
11. 最终切换前暂停旧站内容写入，重新备份同步；切换域名后验证。
    未经用户明确确认不要停用或删除 Railway 服务、卷或数据库。

SMTP 未配置前不要承诺密码重置邮件可用。数据迁移、HTTPS、备份和上线验证
完成前，本目录仅可作为部署候选配置。
